# TaskFlow — продукт для управления проектами и задачами

Монорепозиторий из трёх частей, работающих с одним API:

- `backend/` — REST API (Node.js + Express + TypeScript + PostgreSQL через Prisma)
- `web/` — веб-приложение (React + Vite + TypeScript), одновременно работает как PWA
- `mobile/` — нативное мобильное приложение для iOS/Android (React Native + Expo)

## Функциональность

- Регистрация/вход по email и паролю (JWT)
- Команды (кадровый пул департамента) и проекты внутри команды
- **Роли на уровне проекта**: OWNER / ADMIN / MEMBER — доступ к проекту и его задачам только у явно добавленных участников, управление ролями у OWNER/ADMIN
- Задачи: статусы (To Do / In Progress / Done), приоритет, дата начала и дедлайн, исполнитель
- **Делегирование задач**: смена исполнителя у уже назначенной задачи автоматически фиксируется как делегирование (кто кому передал) и уведомляет нового исполнителя
- Канбан-доска с перетаскиванием задач между статусами (веб) / кнопками смены статуса (мобильное)
- **Диаграмма Ганта** по проекту (переключатель «Канбан / Гант» на веб-доске)
- Комментарии к задачам
- **Вложения к задачам** — загрузка файлов (веб: drag&drop/выбор файла; мобильное: выбор из файловой системы устройства)
- Уведомления в приложении + **push-уведомления на мобильном** (Expo Push): назначение, делегирование, смена статуса, новый комментарий, новое вложение, добавление в команду/проект

## Быстрый старт (локальное тестирование)

### 1. База данных

```bash
docker compose up -d postgres
```

Если Docker недоступен, подойдёт любой локальный/облачный PostgreSQL — просто пропишите `DATABASE_URL` в `backend/.env`.

### 2. Backend

```bash
cd backend
cp .env.example .env
npm install
npm run prisma:migrate   # создаёт таблицы в PostgreSQL
npm run prisma:seed      # (опционально) наполняет БД демо-данными для теста
npm run dev               # http://localhost:4000
```

Сид-скрипт (`npm run prisma:seed`) создаёт демо-команду «МБН — Департамент интегрированного планирования», 5 демо-сотрудников и проект «S&OP: внедрение IBP» с несколькими задачами на разных стадиях — удобно, чтобы сразу увидеть канбан, Гант и роли, не заводя данные руками. Пароль у всех демо-пользователей: `password123` (email вида `anna@demo.local`, `boris@demo.local`, …).

### 3. Веб-приложение

```bash
cd web
npm install
npm run dev                # http://localhost:5173, проксирует /api на backend
```

Веб-приложение можно установить на телефон как PWA (кнопка «Добавить на главный экран» в браузере) — быстрый способ получить мобильную версию без публикации в стор, но без push-уведомлений (они реализованы только в нативном mobile-приложении).

### 4. Мобильное приложение (React Native / Expo)

```bash
cd mobile
npm install
npm start                  # откроется Expo Dev Tools / QR-код
```

Откройте QR-код приложением **Expo Go** (iOS/Android) на телефоне, подключённом к той же Wi-Fi сети, что и компьютер с backend.

По умолчанию мобильное приложение обращается к `http://10.0.2.2:4000/api` (Android-эмулятор) или `http://localhost:4000/api` (iOS-симулятор). Для реального телефона в локальной сети укажите IP компьютера:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.50:4000/api npm start
```

Если тестировщики не в одной сети с backend (например, тестируют удалённо), поднимите туннель, например `npx localtunnel --port 4000` или ngrok, и укажите публичный URL в `EXPO_PUBLIC_API_URL`.

## Тестирование push-уведомлений

Push-токен регистрируется автоматически при входе в мобильное приложение (запрашивается разрешение на уведомления). Чтобы `expo-notifications` мог получить токен, у проекта должен быть привязан Expo/EAS project id:

```bash
cd mobile
npx eas init        # один раз — привяжет проект к вашему Expo-аккаунту и впишет ID в app.json
```

После этого push будет приходить даже при запуске через Expo Go — отдельная сборка (`eas build`) для этого не обязательна, она нужна только для публикации в App Store / Google Play.

Проверить вручную: откройте приложение на телефоне (это регистрирует push-токен), затем на другом устройстве/через веб делегируйте задачу этому пользователю или оставьте комментарий — придёт push.

## Развёртывание в облаке (чтобы был рабочий URL и мобильное приложение на телефоне)

Репозиторий уже содержит конфиги для деплоя одним кликом: `render.yaml` (backend + PostgreSQL), `web/vercel.json` и `web/netlify.toml` (веб), `mobile/eas.json` (мобильная сборка). Всё это выполняется на стороне Render/Vercel/Expo — не из этой сессии — потому что у неё нет доступа к открытому интернету и к вашим устройствам. Ниже — точный порядок действий.

### Шаг 1. Backend + база данных → Render

1. Зайдите на [render.com](https://render.com) и войдите через GitHub.
2. **New → Blueprint**, выберите репозиторий `mail915/11`, ветку `claude/project-task-management-app-jze0zm` (или ту, в которую смержите изменения).
3. Render прочитает `render.yaml`, создаст PostgreSQL и веб-сервис `taskflow-backend`, сам сгенерирует `JWT_SECRET` и подключит `DATABASE_URL`. Нажмите **Apply**.
4. После деплоя (несколько минут — первая миграция БД выполнится автоматически) скопируйте публичный URL сервиса, например `https://taskflow-backend-xxxx.onrender.com`. Проверьте, что `https://<URL>/health` отвечает `{"status":"ok"}`.
5. (Опционально) откройте Shell сервиса в Render и выполните `npm run prisma:seed`, чтобы сразу получить демо-данные и тестовых пользователей (пароль `password123`).

> Бесплатные тарифы и их условия у хостингов периодически меняются — проверьте актуальные лимиты Render на момент деплоя. Если бесплатный план Postgres недоступен, подойдёт любой другой управляемый Postgres (Railway, Neon, Supabase) — просто пропишите его `DATABASE_URL` в переменных окружения сервиса вручную.

### Шаг 2. Веб-приложение → Vercel

1. На [vercel.com](https://vercel.com) → **Add New → Project**, подключите тот же репозиторий.
2. В настройках проекта укажите **Root Directory: `web`** (важно — иначе Vercel будет собирать корень монорепо).
3. Добавьте переменную окружения **`VITE_API_URL`** = URL backend из шага 1 (без `/api` на конце, например `https://taskflow-backend-xxxx.onrender.com`).
4. Deploy. Через минуту получите постоянную ссылку вида `https://taskflow-xxxx.vercel.app` — открывается в любом браузере, с неё же можно установить PWA на телефон («Добавить на главный экран»).

(Альтернатива — Netlify: то же самое, но Base directory = `web`, конфиг уже есть в `web/netlify.toml`.)

### Шаг 3. Мобильное приложение на ваш телефон

Быстрее всего — без сборки, через Expo Go, с уже развёрнутым backend:

```bash
cd mobile
npm install
EXPO_PUBLIC_API_URL=https://taskflow-backend-xxxx.onrender.com/api npx expo start
```

Отсканируйте QR-код приложением **Expo Go** (App Store / Google Play) — телефон и компьютер не обязаны быть в одной сети, если используете `npx expo start --tunnel`.

Если нужен полноценный установочный файл (без Expo Go, значок приложения на экране) — на Android это делается без App Store:

```bash
npm install -g eas-cli
eas login                      # ваш бесплатный аккаунт Expo
eas build --platform android --profile preview
```

Профиль `preview` уже настроен в `mobile/eas.json` — перед запуском замените в нём `YOUR-BACKEND.onrender.com` на реальный адрес backend. Сборка идёт в облаке Expo (10–20 минут), в конце вы получите ссылку на `.apk` — откройте её на Android-телефоне и установите (Android спросит разрешение на установку из «неизвестных источников», это нормально для внутреннего тестирования).

Для iOS без App Store такой возможности нет — Apple требует либо TestFlight (нужен платный Apple Developer аккаунт, $99/год), либо Expo Go. Для пилота внутри компании обычно достаточно Expo Go на iOS и APK на Android.

### Масштаб на 50–80 сотрудников

Архитектура (один backend-процесс + один Postgres) спокойно держит 50–80 пользователей без каких-либо изменений — это не вопрос производительности. Единственное реальное ограничение бесплatного/базового плана Render — **вложения к задачам хранятся на локальном диске сервиса и стираются при передеплое/перезапуске** (ephemeral filesystem). Для пилота это не критично; если вложения должны быть постоянными — подключите платный instance с persistent disk на Render, либо (более правильное решение для продакшена) перевести хранение файлов на S3-совместимое хранилище — это можно сделать отдельной задачей позже.

Не забудьте: сид-скрипт с демо-паролями (`password123`) — только для теста; для реальных сотрудников создавайте аккаунты через обычную регистрацию.

## Архитектура

```
   ┌────────────┐        ┌────────────┐
   │  web (PWA) │        │   mobile   │
   │ React+Vite │        │ Expo/RN    │
   └─────┬──────┘        └─────┬──────┘
         │        REST/JSON    │
         └──────────┬──────────┘
                     │
              ┌──────▼──────┐
              │   backend   │
              │ Express API │──── Expo Push API (push-уведомления)
              └──────┬──────┘
                     │ Prisma
              ┌──────▼──────┐
              │ PostgreSQL  │
              └─────────────┘
```

Модель доступа: `Team` (кадровый пул департамента/юнита) → `Project` (рабочее пространство с собственными ролями `ProjectMember: OWNER/ADMIN/MEMBER`) → `Task`. Добавить сотрудника в проект можно только если он уже состоит в команде — так проекты остаются видимыми только нужному кругу людей даже при 50–80 сотрудниках в департаменте.
