# TaskFlow — продукт для управления проектами и задачами

Монорепозиторий из трёх частей, работающих с одним API:

- `backend/` — REST API (Node.js + Express + TypeScript + PostgreSQL через Prisma)
- `web/` — веб-приложение (React + Vite + TypeScript), одновременно работает как PWA
- `mobile/` — нативное мобильное приложение для iOS/Android (React Native + Expo)

## Функциональность

- Регистрация/вход по email и паролю (JWT)
- Команды (кадровый пул департамента) и проекты внутри команды
- **Роли на уровне проекта**: OWNER / ADMIN / MEMBER — доступ к проекту и его задачам только у явно добавленных участников, управление ролями у OWNER/ADMIN
- Задачи: статусы (To Do / In Progress / Done), приоритет, дата начала и дедлайн, исполнитель
- **Делегирование задач**: смена исполнителя у уже назначенной задачи автоматически фиксируется как делегирование (кто кому передал) и уведомляет нового исполнителя
- Канбан-доска с перетаскиванием задач между статусами (веб) / кнопками смены статуса (мобильное)
- **Диаграмма Ганта** по проекту (переключатель «Канбан / Гант» на веб-доске)
- Комментарии к задачам
- **Вложения к задачам** — загрузка файлов (веб: drag&drop/выбор файла; мобильное: выбор из файловой системы устройства)
- Уведомления в приложении + **push-уведомления на мобильном** (Expo Push): назначение, делегирование, смена статуса, новый комментарий, новое вложение, добавление в команду/проект

## Быстрый старт (локальное тестирование)

### 1. База данных

```bash
docker compose up -d postgres
```

Если Docker недоступен, подойдёт любой локальный/облачный PostgreSQL — просто пропишите `DATABASE_URL` в `backend/.env`.

### 2. Backend

```bash
cd backend
cp .env.example .env
npm install
npm run prisma:migrate   # создаёт таблицы в PostgreSQL
npm run prisma:seed      # (опционально) наполняет БД демо-данными для теста
npm run dev               # http://localhost:4000
```

Сид-скрипт (`npm run prisma:seed`) создаёт демо-команду «МБН — Департамент интегрированного планирования», 5 демо-сотрудников и проект «S&OP: внедрение IBP» с несколькими задачами на разных стадиях — удобно, чтобы сразу увидеть канбан, Гант и роли, не заводя данные руками. Пароль у всех демо-пользователей: `password123` (email вида `anna@demo.local`, `boris@demo.local`, …).

### 3. Веб-приложение

```bash
cd web
npm install
npm run dev                # http://localhost:5173, проксирует /api на backend
```

Веб-приложение можно установить на телефон как PWA (кнопка «Добавить на главный экран» в браузере) — быстрый способ получить мобильную версию без публикации в стор, но без push-уведомлений (они реализованы только в нативном mobile-приложении).

### 4. Мобильное приложение (React Native / Expo)

```bash
cd mobile
npm install
npm start                  # откроется Expo Dev Tools / QR-код
```

Откройте QR-код приложением **Expo Go** (iOS/Android) на телефоне, подключённом к той же Wi-Fi сети, что и компьютер с backend.

По умолчанию мобильное приложение обращается к `http://10.0.2.2:4000/api` (Android-эмулятор) или `http://localhost:4000/api` (iOS-симулятор). Для реального телефона в локальной сети укажите IP компьютера:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.50:4000/api npm start
```

Если тестировщики не в одной сети с backend (например, тестируют удалённо), поднимите туннель, например `npx localtunnel --port 4000` или ngrok, и укажите публичный URL в `EXPO_PUBLIC_API_URL`.

## Тестирование push-уведомлений

Push-токен регистрируется автоматически при входе в мобильное приложение (запрашивается разрешение на уведомления). Чтобы `expo-notifications` мог получить токен, у проекта должен быть привязан Expo/EAS project id:

```bash
cd mobile
npx eas init        # один раз — привяжет проект к вашему Expo-аккаунту и впишет ID в app.json
```

После этого push будет приходить даже при запуске через Expo Go — отдельная сборка (`eas build`) для этого не обязательна, она нужна только для публикации в App Store / Google Play.

Проверить вручную: откройте приложение на телефоне (это регистрирует push-токен), затем на другом устройстве/через веб делегируйте задачу этому пользователю или оставьте комментарий — придёт push.

## Пилот на 50–80 сотрудников — как развернуть для теста

Для 50–80 пользователей текущая архитектура (один Node-процесс + один PostgreSQL) более чем достаточна без каких-либо изменений — это не вопрос масштабирования, а вопрос доступности сервиса тестировщикам вне вашего компьютера. Варианты, от самого быстрого к самому «прод-подобному»:

1. **Всё на одной машине в офисной сети** (самый быстрый способ для пилота внутри компании):
   - `docker compose up -d postgres`, backend через `npm run dev` (или `pm2 start npm --name taskflow-api -- run start` после `npm run build`) на сервере/рабочей станции в локальной сети;
   - веб — `npm run build`, раздать `web/dist` любым статическим сервером (nginx, `npx serve dist`) на той же машине;
   - сотрудники заходят на веб по внутреннему IP/DNS, мобильное — через Expo Go с `EXPO_PUBLIC_API_URL`, указывающим на тот же внутренний адрес.

2. **Облачный хостинг** (если нужен доступ не из офисной сети):
   - backend + PostgreSQL — любой PaaS с управляемым Postgres (Render, Railway, Fly.io) или свой сервер с Docker Compose;
   - веб — статический хостинг (Vercel, Netlify, Cloudflare Pages) с проксированием `/api` на backend-домен;
   - мобильное — `eas build --profile preview` + внутреннее распространение (TestFlight для iOS, Play Internal Testing для Android) — не требует публикации в сторах, ссылку/QR можно разослать 50–80 тестировщикам напрямую.

3. Для быстрого первого прогона без нативной сборки достаточно варианта 1 + Expo Go — этого хватит, чтобы дать доступ всем 50–80 сотрудникам департамента для обратной связи, прежде чем инвестировать в `eas build`.

Независимо от варианта — не забудьте сменить `JWT_SECRET` в `backend/.env` на случайное значение и не используйте сид-скрипт с демо-паролями в чём-то похожем на прод.

## Архитектура

```
   ┌────────────┐        ┌────────────┐
   │  web (PWA) │        │   mobile   │
   │ React+Vite │        │ Expo/RN    │
   └─────┬──────┘        └─────┬──────┘
         │        REST/JSON    │
         └──────────┬──────────┘
                     │
              ┌──────▼──────┐
              │   backend   │
              │ Express API │──── Expo Push API (push-уведомления)
              └──────┬──────┘
                     │ Prisma
              ┌──────▼──────┐
              │ PostgreSQL  │
              └─────────────┘
```

Модель доступа: `Team` (кадровый пул департамента/юнита) → `Project` (рабочее пространство с собственными ролями `ProjectMember: OWNER/ADMIN/MEMBER`) → `Task`. Добавить сотрудника в проект можно только если он уже состоит в команде — так проекты остаются видимыми только нужному кругу людей даже при 50–80 сотрудниках в департаменте.
